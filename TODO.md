# Training roadmap — two modalities

Working document, not part of the release. `data/` now ships `intensity_filtered`
and `range_filtered` as paired renderings of the same 1,088 frames. `results/`
covers the intensity sweep only. This is the path from there to a defensible
two-modality result.

## Where things stand

| | |
|---|---|
| Published baselines | 15 runs, intensity_filtered, seed 0, stock Ultralytics defaults |
| Sweep cost | 10.7 h GPU train time total (0.21–1.75 h per run) on the RTX 2080 Ti |
| Range sweep | not run — config ready at `configs/train_range_filtered.yaml` |
| Labels | identical across modalities, so every geometry statistic is shared |
| Free disk | 6.4 TB; a sweep's `run/` tree is ~2.5 GB |

### One finding that shapes everything below

The frames are 16-bit single-channel PNGs, but Ultralytics loads them with
`cv2.IMREAD_COLOR`. Measured on `0001.png`:

- 18,754 distinct 16-bit values collapse to **167 distinct 8-bit values**
- the result is **three identical channels** — two thirds of the input tensor is
  a duplicate of the first

So the published baselines already train on 8-bit, and a range sweep will too.
That does not invalidate the comparison — both modalities go through the same
pipeline, so the modality is still the only variable — but it means:

1. Quantization loss is larger for range, where the stored value is absolute
   distance, than for intensity.
2. **Two input channels are currently free.** Packing intensity into one and
   range into another costs nothing and needs no code change. Verified: a packed
   3-channel 8-bit PNG round-trips through `cv2.imread` byte-for-byte, channels
   intact. This is the cheapest real experiment available and it is Phase 4.

## Phase 3 — The comparison  *(first pass done — see `result.md`)*

**Result:** range_filtered wins 14 of 15 on mask mAP50-95 (mean +1.28, sign test
p < 0.001) and 15 of 15 on box mAP50-95 (mean +3.60). `fence_pole` moves the
other way (-1.82, 2/15 wins) — the one part of this that still needs explaining.
Generated by `scripts/compare_modalities.py`.


This is where the scientific care goes. The sweep is **untuned, single-seed, by
design** — that was defensible for reference baselines, and it is weaker ground
for a per-model claim about which modality is better.

- [ ] Build a paired comparison table: for each of the 15 models (20 head rows),
      mask mAP50-95 and box mAP50-95 on intensity, on range, and the delta
- [ ] Read the **sign of the delta across all 20 rows**, not any single row. 20
      paired comparisons of the same architectures under identical settings is
      real evidence about the modality; one model's 0.8-point gap is not.
- [ ] Break the delta down per class. `fence_pole` has the thinnest masks
      (median 30 px) and is the most likely to move — a range image may separate
      a thin pole from its background better than intensity, or may not survive
      the 8-bit quantization. Either outcome is worth reporting.
- [ ] Bound run-to-run noise before claiming any small delta is real: rerun **one
      mid-size model** (`yolo11m-seg`, 0.6 h) at seeds 1 and 2 on both
      modalities. Four extra runs (0.6 h each, ~2.5 h total), and it converts
      "range is 0.6 points better" from a number into a claim.

  ```bash
  # sketch — a scratch config per seed, or add a seed override to the sweep yaml
  ```

- [ ] Decide the framing honestly. If the deltas sit inside seed noise, the
      finding is *"the two renderings are equivalent under stock defaults"* —
      which is a perfectly publishable result for a dataset paper, and more
      credible than a ranking the evidence does not support.

## Phase 4 — Fused modality (highest value per hour)

Two input channels are currently duplicates. Fill them.

- [ ] Write `scripts/build_fused.py`: for each frame, read the intensity and
      range 8-bit renderings and write one 3-channel PNG —
      `ch0 = intensity`, `ch1 = range`, `ch2 = ` a third signal or a mean.
      Round-trip through `cv2.imread` is already verified lossless.
- [ ] Land it as a third modality at `data/{split}/fused/{images,labels}`, with
      the same duplicated label set. `dataset_analysis.py`'s `MODALITIES` tuple
      and mirror check extend to it by adding one string.
- [ ] Add `data/data_fused.yaml` and `configs/train_fused.yaml`, mirroring the
      range pair
- [ ] Run the sweep (another 12–14 h), or just the three mid-size models first
      if you want a read before committing the night
- [ ] Compare three ways: intensity / range / fused

**Why this is the strongest cheap move:** it needs no code changes to
Ultralytics, no new dependency, no change to the training recipe, and it uses
input capacity the current pipeline throws away. If fusion beats both single
modalities, that is the paper's headline. If it does not, that is a clean
negative result about early fusion at 8-bit.
